# Курс из первого сообщения в Direct: SendPulse → amoCRM → дашборд

Задача: по каждой переписке из Instagram понимать, какой курс человек назвал
первым сообщением, ставить эту метку в сделку amoCRM и видеть путь до денег
в дашборде «Путь клиента».

## Как это работает

```
Реклама → человек жмёт кнопку «Minecraft: сколько стоит?» → Direct
   │
   ├── amoCRM (своя интеграция с Instagram) создаёт сделку
   │
   └── SendPulse (AI-консультант) получает то же сообщение
          │ глобальный вебхук «Входящие сообщения»
          ▼
   webhook.gs (проект «IG webhook») — определяет курс по словарю
          │ лист «Курсы из Direct»: ник, имя, курс, текст
          ▼
   pplTagDirectCourses (проект «ФБ», раз в 10 минут)
          │ находит сделку amoCRM по событию «входящее сообщение»
          │ (а если его нет — по нику/имени и времени)
          ▼
   сделка: utm_campaign = «Minecraft», тег «курс: Minecraft»
          │ обычная выгрузка RAW_leads + живая дельта
          ▼
   «Путь клиента» → блок «Курс из первого сообщения в Direct»
```

Почему так, а не проще:

- **UTM-метки** в рекламе с переходом в Direct не передаются — ссылки нет.
- **Salesbot в amoCRM** не подтверждённо видит текст первого сообщения, а
  его запуск на старте беседы мог бы прервать ботов маркетолога.
- **ID объявления** Meta присылает только приложениям, прошедшим проверку
  (App Review), а она ждёт подтверждения компании.
- SendPulse уже подключён к Direct и сообщения получает — достаточно
  включить у него вебхук.

## Что где лежит

| Часть | Где | Что делает |
|---|---|---|
| `apps-script/webhook.gs` | проект Apps Script «IG webhook» | принимает вебхук SendPulse, определяет курс (`spCourse_`), пишет лист |
| лист «Курсы из Direct» | та же таблица, что `SHEET_ID` | `ts, service, bot, contact_id, username, name, course, prefix, text, ad_id, ad_title, status, lead_id, tries` |
| лист «SendPulse: образцы» | та же таблица | первые 30 событий вебхука как есть — чтобы видеть реальную структуру |
| `pplTagDirectCourses` | `apps-script/people.gs`, проект «ФБ» | ставит `utm_campaign` (курс), `utm_content` (ID объявления) и тег в сделку amoCRM |
| `by_course` | `pplAlfaRevenueCore_` + `api/core.php` | разрез выручки по курсу |
| блок «Курс из первого сообщения» | `people.html` | таблица на странице |
| `revenue.direct` | `pplDirectRows_` → `pplAlfaRevenueCore_` | по строке на человека: лист + сделка из amoCRM живьём (этап, причина отказа) + Альфа и оплаты |
| таблица «Кто написал в Direct» | `people.html`, `renderDirect` | когда, аккаунт, что написал, где сейчас сделка, выручка |

Оба листа лежат в таблице «ФейсБук» и создаются сами на первом входящем
сообщении. Пока их нет — значит, после включения вебхуков никто не писал.

SendPulse сам отличает переписки из рекламы (раздел бота «Эффективность
рекламы» → «Последние чаты из рекламы»), значит referral от Meta до него
доходит. Приёмник ищет `ad_id` по всему событию (`spReferral_`).

С 27.09.2026 строка пишется на **каждого**, кто написал, — одна на
человека за 7 дней (`spSeenRecently_`), курс в ней есть, если назван.
Строка без курса не мешает записать строку с курсом: «Здравствуйте» и
следом «Minecraft: сколько стоит?» дадут две строки, таблица покажет одну.
Раньше писались только сообщения с курсом, и новые люди, пришедшие
отметкой в сторис, в таблицу не попадали.

Словарь курсов — `SP_COURSES` в `webhook.gs`, названия как варианты поля
«Курс в заявке» в amoCRM. Новое направление в рекламе → одна строка в
словаре.

Статусы в листе:

| status | значит |
|---|---|
| пусто / `retry` | ждёт: сделка могла ещё не появиться, пробуем раз в 10 минут |
| `ok` | метка поставлена, `lead_id` — сделка |
| `has_value` | у сделки utm_campaign уже был — его не трогали, добавлен только тег |
| `old_lead` | amoCRM подшил переписку в старую сделку клиента — поставлен только тег (если есть курс), поля не тронуты (иначе курс приписался бы к прошлой заявке и её выручке) |
| `no_course` | курса нет, но сделка заведена на эту переписку — новый человек; в сделку ничего не пишется |
| `relinked` | была `old_lead`, но в течение 14 дней менеджер завёл на того же контакта новую сделку: строка переключена на неё (`lead_id`), в сделку записаны курс и тег, как в свежую |
| `no_contact` | за 2 часа не нашли контакт с таким ником/именем |
| `no_lead` | контакт есть, но подходящей сделки нет |
| `skip_service` | сообщение не из Instagram (у SendPulse может быть и другой мессенджер) |
| `skip_empty` | в строке нет времени (до 27.09.2026 — ещё и нет ни курса, ни ID объявления) |

## Включение (один раз)

1. **Проект «IG webhook»**: заменить код на `apps-script/webhook.gs` из
   репозитория → сохранить → «Начать развертывание → Управление
   развертываниями → карандаш → Версия: Новая → Развернуть». Адрес
   `/exec` не меняется, Meta-подписка не ломается.
2. **Проект «ФБ»**: обновить `people.gs` тем же способом, новая версия
   развёртывания. Затем в редакторе один раз запустить
   `pplSetupDirectCourseTrigger` — появится триггер раз в 10 минут.
3. **SendPulse** (делает владелица или маркетолог — в адресе секрет):
   чат-бот Instagram → **Настройки бота → Вебхуки** → включить → URL =
   тот же адрес, что вписан в Meta как Callback URL:
   `https://script.google.com/macros/s/<ID IG webhook>/exec?s=<URL_SECRET>`
   → событие **«Входящее сообщение»** → сохранить. Повторить для каждого
   Instagram-бота. Сделано 26.09.2026 для всех четырёх: «Программирование
   и дизайн для детей» (CODDY), «Детский клуб развития Прознание
   Могилёв», «Прознание Могилёв: каникулы…», «Детали». Секрет у всех
   один; сверять его можно хешем значения поля, не выводя сам секрет.
4. **Проверка**: написать в Direct «Minecraft: тест». В проекте «IG
   webhook» → «Количество выполнений» появляется `doPost`, в таблице —
   листы «SendPulse: образцы» и «Курсы из Direct». Минут через 10 у строки
   `status = ok`, а в сделке — utm_campaign «Minecraft» и тег «курс:
   Minecraft». Учтите: тестовое сообщение тоже создаст сделку в amoCRM,
   и на него ответит AI-консультант.

## Таблица «Кто написал в Direct»

Строка — человек из листа «Курсы из Direct» за выбранный период (по дате
сообщения): все, кто назвал курс, и все новые переписки без курса
(`no_course`). Текущие разговоры старых контактов без курса
(`old_lead`, `retry` и прочие) `pplDirectPick_` отсекает ещё до
запросов в amoCRM, а человек со строкой и без курса, и с курсом остаётся
одной строкой — с курсом. Страница повторяет этот фильтр у себя (по
`client` и `lead_id`): версия 42 скрипта его ещё не знает. Сделку
`pplDirectRows_` берёт из amoCRM живьём с
`with=loss_reason`: в RAW_leads нет причины отказа, а этап у сделок,
тронутых сегодня, там утренний. «Где сейчас»: «Стал клиентом» (этап 142),
«Отказ» с причиной менеджера (143; 26.09.2026 причина стояла у 99 из 100
закрытых сделок за два месяца), «В работе» с названием этапа, «Ищем
сделку» (строка ещё в `retry`) или «Сделку не нашли». Выручка считается
по тем же правилам, что и `by_course`: оплаты в Альфе с даты заявки. Если
amoCRM подшил переписку в сделку, заведённую раньше (`client`, на странице
— «уже был в amoCRM»: часто действующий клиент, но бывает и «Записан на
пробное»), этап показываем, а выручку этой рекламе не приписываем — в
колонке «—»; выигранная давно сделка подписана «Клиент», а не «Стал
клиентом».

Почему переписка попадала в старую сделку: в amoCRM («Настройки → Чаты и
мессенджеры → Беседы») до 28.09.2026 стояло правило «новая сделка, только
если у клиента нет ни активных, ни закрытых сделок». Тогда любой, у кого
когда-то была сделка, писал в неё, даже в проигранную: так 27.09 вопрос
про математику лёг в летнюю сделку «Интенсивов», и менеджер завёл новую
руками. К этому дню таких строк `old_lead` было 150 из 368. 28.09 правило
сменили на «новая сделка, если у клиента нет активных»: человек только с
закрытыми сделками получает новую, и задача находит её как свежую. Правило
работает, только когда открытой беседы нет. Сделку, заведённую
менеджером вручную, подхватывает перепривязка (`pplRelinkOldLeads_`, в той
же задаче раз в 10 минут, но не чаще раза в час). Она смотрит контакты
строк `old_lead` не старше 14 дней: если у того же контакта появилась
сделка, созданная после сообщения, строка переключается на неё
(`relinked`). В сделку ложатся курс и тег, в таблице видна её стадия,
оплаты идут этому обращению. Сделку забирает самое свежее обращение
контакта; сделку, у которой уже есть своя строка, не трогаем. Первый
проход идёт по всем `old_lead` сразу. Если сделку завели на новый
контакт-дубль того же человека, связь не найдётся.

Имена скрыты кнопкой «Показать имена», как и везде на
странице; инициалы — только у слов с буквы (эмодзи и «•» из имени
профиля пропускаются). Имя аккаунта «ДЕТСКИЙ КЛУБ…» SendPulse отдаёт с
«й» в разложенном виде (NFD), поэтому `pplShortBot_` и `shortAccount`
сначала нормализуют строку. Текст сообщения — чужой ввод, страница
выводит его только экранированным. В PHP-пакете (`api/people.php`) список
пока пустой: лист SendPulse читает только Apps Script.

## Таблица «По объявлениям» и расход по курсам

Колонки «Написали / Сделки / Оплатили / Выручка» раньше ждали кликов из
вебхука Meta (App Review) и были пустыми. Теперь их заполняют люди из
Direct (`pplDirectAdStats_`, 27.09.2026):

- **точно по объявлению**, если SendPulse передал ID объявления
  (`referral` в событии). Раз передал хоть однажды за период, строки без
  ID считаются не рекламными и по курсу не раскладываются;
- **иначе по курсу**: курс объявления — из названия кампании («природная
  глина сообщение» → Глина), не нашёлся — из названия объявления; курс
  человека — из первого сообщения. Одно объявление на курс — цифры его;
  несколько — у каждого общая цифра курса (`attr: 'shared'`, на странице
  «≈»), в «Итого» (`ads_total`) она входит один раз. Объявления без курса
  в названии («МЦО», «подготовка к школе» — их нет в словаре) остаются
  пустыми.

«Сделки» — только новые (не «уже был в amoCRM»), выручка — как в ядре:
оплаты в Альфе с даты заявки. CAC и ROAS — в валюте Альфы: расход Meta
переводится той же логикой, что в сводке канала (одна валюта или
свойство `FX_RATE`, `pplToAmo_`); перевести нечем — прочерк.

В разрезе по курсам (`by_course`) появились «Расход», CAC и ROAS
(`pplCourseSpend_`): расход объявлений с этим курсом в названии кампании;
курсы, на которые тратили без заявок, добавляются строкой; расход
объявлений без курса — в «Курс не определён».

Словарь курсов в `people.gs` (`PPL_COURSES`) — копия `SP_COURSES` из
`webhook.gs`: это разные проекты Apps Script. Тест сверяет копии, новый
курс добавлять в оба файла (и выпускать обе версии).

## Досыпка истории с 1 сентября (`pplBackfillDirect`)

Приёмник пишет людей с 26.09.2026 (с 27.09 — всех, до того — только
назвавших курс). Прошлое берётся из SendPulse: официальный API
(`https://api.sendpulse.com/instagram`, ключ в свойстве `SP_API_KEY` —
SendPulse → «Доступ к API» → «Ключи API»; «Учётные данные» не
перевыпускать, это ломает другие интеграции) отдаёт чаты бота (`/chats`)
и все сообщения переписки (`/chats/messages`).

`pplBackfillDirect` запускается один раз из редактора: проходит по
четырём Instagram-ботам, по каждому контакту с активностью после 1.09
берёт входящие за [1.09, 27.09 12:43) и дописывает строки по правилам
приёмника — первая за 7 дней, строка с курсом отдельно; уже записанное
приёмником (±7 дней) не дублирует. Порциями по 3,5 минуты, продолжение —
триггер `pplBackfillDirectNext` через 7 минут (снимается сам), состояние —
в свойстве `DIRECT_BACKFILL`. В конце лист сортируется по времени (под
замком: `pplTagDirectCourses` пишет статус по номеру строки и теперь
тоже берёт замок). Первые сообщения первого запуска — в листе «SendPulse:
история, образцы», чтобы сверить формат `data` с кодом. Досыпанные
строки разбирает обычная задача меток (60 за запуск), для сентябрьских
сделок — те же правила: `utm_campaign` и тег в новых, тег в старых.

Страница получает последних 300 человек (`pplDirectCap_`, иначе ответ не
влезает в кэш), цифры по объявлениям и курсам считаются по всем.

## Ограничения

- Метка ставится только тем, кто назвал курс. Общие вопросы («что
  подобрать для 4–6 лет») размечает менеджер вручную.
- Сделка ищется прежде всего по событию amoCRM «входящее сообщение»
  (`incoming_chat_message`, источник `instagram_business`): оно приходит
  на 2–6 секунд раньше вебхука SendPulse, берётся ближайшее. Так находится
  и старая сделка клиента, чей контакт менеджер переименовал. Если двое
  написали с разницей меньше 5 секунд, по событию не угадываем.
- Запасной путь — по имени контакта amoCRM: оно должно совпасть с ником
  или именем в Instagram. Регистр, знаки, эмодзи и порядок слов не важны:
  amoCRM называет контакт «Фамилия Имя», и профиль «Jane Mp» становится
  контактом «Mp Jane».
- Apps Script отвечает на POST редиректом (302). Meta это принимает; если
  SendPulse начнёт считать доставку ошибкой — приёмник переносится на
  `app.proznanie.club` (пакет переезда в `api/`).
